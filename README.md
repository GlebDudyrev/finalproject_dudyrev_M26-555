# ValutaTrade Hub

**ValutaTrade Hub** — консольное приложение на Python для учёта виртуальных валютных портфелей и моделирования операций покупки и продажи фиатных и криптовалют. Пользователи могут регистрироваться, управлять кошельками, отслеживать стоимость портфеля и получать актуальные курсы валют.

Курсы загружаются из **CoinGecko** и **ExchangeRate-API** через подсистему Parser Service. Полученные значения сохраняются в JSON-файлах: отдельно поддерживаются кеш последних котировок и история обновлений.

Приложение предназначено для учебного моделирования. **Реальные денежные операции не выполняются.** При регистрации пользователю начисляется 1 000 виртуальных USD.

## Возможности

- Регистрация и авторизация пользователей с хранением хешей паролей и индивидуальных солей.
- Управление портфелем из отдельных валютных кошельков.
- Покупка и продажа валют за виртуальные USD с проверкой доступного баланса.
- Получение прямых, обратных и перекрёстных курсов, оценка стоимости портфеля в выбранной валюте.
- Обновление котировок из двух внешних API вручную, при истечении срока действия кеша или по расписанию.
- Хранение истории измерений, обработка ошибок внешних сервисов и журналирование торговых операций.

Поддерживаемые валюты: **USD, EUR, GBP, RUB, BTC, ETH, SOL**. USD используется как расчётная валюта при покупке и продаже.

## Требования

- **Python 3.12** или новее.
- **uv** — установка зависимостей и запуск проекта: <https://docs.astral.sh/uv/>.
- Подключение к интернету для получения новых котировок.
- API-ключ **ExchangeRate-API** для обновления фиатных курсов. Для публичного эндпоинта CoinGecko ключ не обязателен.

Основные зависимости указаны в `pyproject.toml`: `requests`, `prettytable`; для проверки стиля используется `ruff`. Разрешённые версии зависимостей зафиксированы в `uv.lock`.

## Установка и запуск

В терминале перейдите в корневой каталог проекта, содержащий `main.py` и `pyproject.toml`:

```bash
uv sync
uv run python main.py
```

После запуска откроется интерактивный интерфейс:

```text
ValutaTrade Hub
Для завершения работы введите exit.
>
```

Команды вводятся **после приглашения `>`**, без префикса `uv run`. Для завершения работы используется `exit` или `Ctrl+D`.

Точка входа приложения — `main.py`.

## Конфигурация

Приложение загружает настройки из `config.json`. По умолчанию на Linux используются следующие пути:

| Назначение | Путь по умолчанию |
|---|---|
| Конфигурация | `~/.config/valutatrade_hub/config.json` |
| Пользователи, портфели и котировки | `~/.local/share/valutatrade_hub/data/` |
| Журналы | `~/.local/state/valutatrade_hub/logs/` |

Поддерживаются стандартные переменные `XDG_CONFIG_HOME`, `XDG_DATA_HOME` и `XDG_STATE_HOME`. При отсутствии файла `config.json` используются значения по умолчанию.

Для изменения настроек создайте каталог и файл конфигурации:

```bash
mkdir -p ~/.config/valutatrade_hub
nano ~/.config/valutatrade_hub/config.json
```

Пример содержимого `config.json`:

```json
{
  "data_dir": "/home/user/projects/finalproject_dudyrev_M26-555/data",
  "log_path": "/home/user/projects/finalproject_dudyrev_M26-555/logs/actions.log",
  "rates_ttl_seconds": 300,
  "default_base_currency": "USD",
  "log_format": "text",
  "parser_scheduler_enabled": false,
  "parser_update_interval_seconds": 300
}
```

Замените `/home/user/projects/finalproject_dudyrev_M26-555` на фактический путь к проекту. В `data_dir` можно указать каталог `data/` из поставки или отдельную директорию. Если путь относительный, он вычисляется относительно каталога с `config.json`.

Параметры конфигурации:

| Ключ | Описание | По умолчанию |
|---|---|---|
| `data_dir` | Каталог JSON-файлов приложения | XDG-каталог данных |
| `log_path` | Путь к журналу торговых операций | XDG-каталог журналов, `actions.log` |
| `rates_ttl_seconds` | Максимальный возраст котировки, сек. | `300` |
| `default_base_currency` | Базовая валюта отображения портфеля и списка курсов | `USD` |
| `log_format` | Формат журналов: `text` или `json` | `text` |
| `parser_scheduler_enabled` | Включение фонового обновления | `false` |
| `parser_update_interval_seconds` | Интервал фонового обновления, сек. | `300` |

Настройки загружаются при старте приложения. После изменения `config.json` приложение необходимо перезапустить.

**Важно:** каталог `data/` в архиве содержит начальные пустые JSON-файлы. Без настройки `data_dir` приложение работает с пользовательским XDG-каталогом, а не с этой папкой проекта.

## Источники курсов и API-ключ

Parser Service использует два источника:

| Сервис | Валюты | Особенности |
|---|---|---|
| [CoinGecko](https://www.coingecko.com/en/api) | BTC, ETH, SOL | Запрос `/api/v3/simple/price`; используются ID `bitcoin`, `ethereum`, `solana` |
| [ExchangeRate-API](https://www.exchangerate-api.com/) | EUR, GBP, RUB | Запрос относительно USD; ответ преобразуется в пары `EUR_USD`, `GBP_USD`, `RUB_USD` |

Ключ ExchangeRate-API передаётся через переменную окружения, а не записывается в исходный код или `config.json`:

```bash
export EXCHANGERATE_API_KEY="ваш_api_ключ"
uv run python main.py
```

Переменную окружения необходимо установить **до запуска** приложения. Не добавляйте действующий ключ в Git и не показывайте его в демонстрационной записи терминала.

Если ключ отсутствует, можно обновить только криптовалютные курсы:

```text
> update-rates --source coingecko
```

Команда `update-rates` без `--source` обращается к обоим источникам. Если один из них недоступен, полученные от второго источника котировки всё равно могут быть сохранены. При этом программа выводит сведения о частичном отказе.

## Команды

Все команды выполняются в интерактивной консоли приложения.

| Команда | Действие |
|---|---|
| `register --username alice --password 1234` | Зарегистрировать пользователя |
| `login --username alice --password 1234` | Авторизоваться |
| `show-portfolio` | Показать кошельки и их общую стоимость в базовой валюте |
| `show-portfolio --base EUR` | Показать стоимость портфеля в EUR |
| `buy --currency BTC --amount 0.005` | Купить 0.005 BTC за виртуальные USD |
| `sell --currency BTC --amount 0.002` | Продать 0.002 BTC за виртуальные USD |
| `get-rate --from BTC --to USD` | Показать курс и обратный курс |
| `update-rates` | Обновить курсы из всех источников |
| `update-rates --source coingecko` | Обновить только криптовалюты |
| `update-rates --source exchangerate` | Обновить только фиатные валюты |
| `show-rates` | Показать сохранённые курсы |
| `show-rates --currency RUB` | Показать курс выбранной валюты |
| `show-rates --top 2` | Показать две самые дорогие криптовалюты в кеше |
| `show-rates --base EUR` | Пересчитать список курсов относительно EUR |
| `exit` | Завершить работу |

Для `buy` и `sell` необходима авторизация. Сумма в `--amount` задаётся **в единицах покупаемой или продаваемой валюты**, а не в USD. При покупке соответствующая сумма списывается с USD-кошелька; при продаже выручка зачисляется на него. Кошелёк новой валюты создаётся автоматически при первой покупке. Покупка и продажа USD за USD не поддерживаются.

Параметры `show-rates` можно комбинировать, например:

```text
> show-rates --top 2 --base EUR
```

### Пример сеанса

Ниже приведена последовательность команд для проверки основных возможностей приложения:

```text
> update-rates
> register --username alice --password 1234
> login --username alice --password 1234
> get-rate --from BTC --to USD
> buy --currency BTC --amount 0.005
> show-portfolio
> sell --currency BTC --amount 0.002
> show-portfolio --base EUR
> show-rates --top 2
> exit
```

Пример вывода операции покупки:

```text
> buy --currency BTC --amount 0.005
Покупка выполнена: 0.0050 BTC по курсу 59337.21 USD/BTC
Изменения в портфеле:
- BTC: было 0.0000 → стало 0.0050
Оценочная стоимость покупки: 296.69 USD
```

Курс **59337.21 USD/BTC приведён только для примера**. Фактические значения зависят от полученных котировок и времени обновления кеша.

## Хранение данных и актуальность котировок

В качестве хранилища используются JSON-файлы:

| Файл | Назначение |
|---|---|
| `users.json` | Пользователи, хеши паролей, соли и даты регистрации |
| `portfolios.json` | Кошельки и балансы пользователей |
| `rates.json` | Последние сохранённые котировки и время их обновления |
| `exchange_rates.json` | История полученных курсов с идентификаторами измерений |

Пароли не сохраняются в открытом виде: применяется PBKDF2-HMAC-SHA256 с индивидуальной солью.

Структура `rates.json`:

```json
{
  "pairs": {
    "BTC_USD": {
      "rate": 59337.21,
      "updated_at": "2025-10-10T12:00:00Z",
      "source": "CoinGecko"
    },
    "EUR_USD": {
      "rate": 1.0786,
      "updated_at": "2025-10-10T12:00:00Z",
      "source": "ExchangeRate-API"
    }
  },
  "last_refresh": "2025-10-10T12:00:01Z"
}
```

Для каждой пары хранится последнее корректное значение. Более старая котировка не заменяет более свежую. История в `exchange_rates.json` позволяет сохранять отдельные измерения без повторного добавления одинаковых идентификаторов.

При выполнении `get-rate`, `buy`, `sell` и `show-portfolio` проверяется срок действия **необходимых для операции** котировок. Если значение отсутствует или устарело, запускается обновление через Parser Service. После обновления кеш проверяется повторно. При недоступности актуального курса операция не выполняется. Фиксированные подставные курсы не используются.

Команда `show-rates` предназначена для просмотра содержимого кеша и **не инициирует обновление**: она может отображать и ранее сохранённые котировки, срок действия которых уже истёк.

Для записи кеша и истории Parser Service использует временный файл с последующей заменой (`os.replace`). Атомарность обеспечивается отдельно для каждого файла.

### Периодическое обновление

Фоновое обновление по умолчанию выключено. Для включения задайте в `config.json`:

```json
{
  "parser_scheduler_enabled": true,
  "parser_update_interval_seconds": 300
}
```

Если в конфигурации уже присутствуют другие ключи, добавьте эти параметры к существующему JSON-объекту.

Планировщик работает в отдельном потоке, не блокирует CLI и запускает первое периодическое обновление после заданного интервала. Ручные и фоновые обновления синхронизируются в рамках одного процесса.

## Обработка ошибок

Приложение проверяет корректность валютных кодов, сумм, доступных остатков и полученных котировок. Основные случаи:

- **Недостаточно средств** — операция отклоняется, текущие балансы не сохраняются с изменениями.
- **Неизвестная валюта** — выводится сообщение и список поддерживаемых кодов.
- **Сбой API, отсутствие ключа или ограничение запросов** — выводится сообщение об ошибке; устаревшие котировки не используются для торговли.
- **Некорректные аргументы** — команда отклоняется без завершения приложения.
- **Повреждённый `rates.json`** — выводится сообщение о повреждённом кеше. Для восстановления сохраните копию файла, удалите повреждённый оригинал и выполните `update-rates`.

Сделки выполняются на виртуальных балансах с типом `float`; приложение не предназначено для реальных финансовых расчётов и не является торговым терминалом.

## Логирование

Файловые журналы настраиваются в `logging_config.py`:

- `actions.log` — результаты `buy`/`sell`, включая ошибочные операции, через декоратор `@log_action`.
- `parser.log` — обновление котировок, обращения к источникам, ошибки и работа планировщика.

Доступны форматы `text` и `json` (по одной JSON-записи в строке). Стандартный уровень — `INFO`; при необходимости конфигурация логгера поддерживает `DEBUG`. Журналы ротируются по достижении **1 МБ**, сохраняются **три резервных файла**. Пароли и API-ключи не записываются как поля торговых событий.

## Структура проекта

```text
finalproject_dudyrev_M26-555/
├── data/
│   ├── users.json
│   ├── portfolios.json
│   ├── rates.json
│   └── exchange_rates.json
├── valutatrade_hub/
│   ├── core/
│   │   ├── models.py          # User, Wallet, Portfolio
│   │   ├── currencies.py      # Currency, FiatCurrency, CryptoCurrency
│   │   ├── exceptions.py      # доменные исключения
│   │   ├── usecases.py        # регистрация, торговля, получение курсов
│   │   └── utils.py           # хеширование и вспомогательные функции
│   ├── infra/
│   │   ├── settings.py        # конфигурация и SettingsLoader
│   │   ├── database.py        # JSON-хранилище и DatabaseManager
│   │   └── utils.py           # чтение и запись JSON
│   ├── parser_service/
│   │   ├── config.py          # ParserConfig
│   │   ├── api_clients.py     # клиенты внешних API
│   │   ├── storage.py         # кеш и история котировок
│   │   ├── updater.py         # RatesUpdater
│   │   └── scheduler.py       # фоновое обновление
│   ├── cli/
│   │   └── interface.py       # разбор команд и вывод
│   ├── decorators.py         # @log_action
│   └── logging_config.py     # форматирование и ротация логов
├── demo/                     # демонстрация работы CLI
├── main.py                   # точка входа
├── pyproject.toml
├── uv.lock
├── .gitignore
└── README.md
```

**Распределение ответственности:** `cli` обрабатывает пользовательский ввод и вывод; `core` содержит модели и правила операций; `infra` отвечает за настройки и хранение данных; `parser_service` получает, проверяет и сохраняет курсы. Компоненты связываются в `main.py`. Parser Service реализован как подсистема приложения, а не как отдельный HTTP-сервер.
